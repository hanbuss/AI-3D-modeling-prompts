# 云嵴山居 · Cloudcrest Villa
### 三层新中式别墅 · 数字化设计与交互模型说明书

> 工程目录：`<repo>/villa`
> 建模引擎：Blender 5.1.2（程序化脚本生成，可一键重建）
> 交互载体：Three.js 离线查看器（旋转 / 分层 / 昼夜 / 标注 / 剖切）

---

## 一、设计命题

新中式的难点不在"加中式元素"，而在**用现代建造逻辑去承接传统的空间秩序**。这份方案定了三条底线：

1. **不做符号堆砌**。不用飞檐斗拱去模仿古建，只用"白墙—深瓦—木格栅—石基座"四件材料语言，让中式感从比例和光影里长出来。
2. **竖向做减法，横向做加法**。三层逐层退台（16×12 → 16×12 → 16×9.4），越往上越轻，屋顶压一层四坡瓦顶收头；平面上则把茶室、静室、庭院这些"慢空间"一层层铺开。
3. **室内外互文**。南向一整面落地玻璃 + 3.4 m 进深的挑檐，把庭院的水、竹、石"框"进客厅；二层阳台与三层露台又把室内生活推到室外。

## 二、场地与朝向

| 项目 | 参数 |
|---|---|
| 用地 | 42 m × 36 m（约 1.5 亩），四周院墙围合 |
| 建筑占地 | 16 m × 12 m = 192 m² |
| 总建筑面积 | 约 495 m²（含阳台、露台） |

## 八、光环境与昼夜

**白天（14:00）**
太阳高度 54°、方位西南，色温 4600 K，能量 4.6；天光用垂直渐变（地面暖灰 → 地平线米白 → 天顶蓝），配 900 W 大面积补光模拟天穹漫射；室内点光源压到 22 W 只做体积感。

**夜间（22:00）**
太阳换月色（0.22，冷蓝 6200 K），天光降到 1/10；9 盏室内点光源升到 130 W（暖 2900 K）；**窗玻璃与灯罩材质自发光**：窗户 1.5、灯罩 2.6，形成"一栋楼亮起来"的夜景——这也是查看器昼夜滑杆驱动的同一套材质。

**材质发光分工**（供程序识别）
- `M_WinGlow`：所有外窗玻璃，白天 emissive≈0.30（弱暖反射），夜间拉到 1.5–3.0。
- `M_LampShade`：吊灯/台灯/落地灯灯罩 + 石灯笼内胆。
- `M_Screen`：电视屏，夜间轻微自发光。

## 九、数字化实现

### 9.1 脚本架构

```
villa/
├── lib/kit.py        几何内核：GB 累积式构建器（12 种图元 + 变换栈 + 材质兜底）
├── lib/mats.py       材质库：57 种 PBR 材质（base/rough/metal/alpha/emissive + 程序化 bump）
├── lib/arch.py       建筑构件：开洞墙、门窗、楼板、栏杆、楼梯、四坡顶、披檐、月亮门、四角亭、腰线
├── lib/furni.py      家具软装：36 类（沙发/床/餐桌/橱柜/浴缸/屏风/灯具/户外家具/石灯笼…）
├── lib/nature.py     植物山石：造型松/红枫/竹林/灌木/景石/睡莲/芦苇/乔木
├── lib/details.py    室内门扇（11 樘）+ 檐角戗檐补件
├── lib/texgen.py     程序化贴图：12 套可平铺 albedo + 法线（纯 numpy）
├── lib/assets.py     成品植被加载：append assets/*.blend，副本共享 mesh
├── prep_assets.py    成品模型预处理：导入→合并→减面→贴图 512→落地归一化
├── build_villa.py    总装：场地→外壳→三层内装→花园→灯光→机位→导出
├── render_shots.py   出图：昼夜两套光照 + 6 机位
├── plan_shots.py     分层平面图：逐层隐藏其余层，正交俯视
├── audit.py          布局审查：浮空 / 沉地 / 穿墙 / 越界 / 互相穿插
├── textures/         12 套 512² 贴图（albedo + normal）+ manifest.json
└── viewer/           Three.js 交互查看器（离线，零构建）
```

**关键设计**：不是"做 1000 个小物体"，而是每个空间/构件累积成一个多材质 mesh。全楼 **225 个网格对象 / 57 种材质 / 12 套贴图**，几何 + 贴图打包成 GLB（15 MB），浏览器直接加载。

**贴图管线**：`lib/texgen.py` 用 numpy 自己写 PNG 编码器，生成 12 套**严格可平铺**的 albedo + 切线空间法线（石膏、深/浅石、大理石、橡木/胡桃木/炭化木、筒瓦、亚麻布、地毯、草坪、砾石）。UV 用**三向 box 投影**（按面法线取主轴、世界坐标除以 2 m），保证任意物体贴图密度一致、不出现拉伸；材质侧用 Mapping 节点按各自 tile 尺寸二次缩放，导出为 glTF 的 `KHR_texture_transform`（three.js 原生支持）。

### 9.2 模型 → 网页的契约

- `villa.glb`：glTF 2.0 binary，Y-up，米制；顶层节点 **`SITE / GARDEN / F1 / F2 / F3 / ROOF`**，每层所有对象挂在该空节点下——查看器的"分层查看"就是切这 6 个节点的 `visible`。
- `rooms.json`：20 条房间记录（`id / zh / en / floor / pos / area / desc`），`pos` 已换算成 glTF 的 Y-up 世界坐标，查看器直接投影成屏幕标签，点标签相机就飞过去。
- 材质命名统一 `M_` 前缀，发光材质固定为 `M_WinGlow` / `M_LampShade`，昼夜滑杆按名字改 `emissiveIntensity`。

```bash
cd <repo>/villa/viewer
python -m http.server 8899
# 浏览器打开 http://127.0.0.1:8899/index.html
```

**重建/改设计**：

```bash
cd <repo>/villa
blender -b --python build_villa.py        # 约 3 s，重生成 blend + glb + rooms.json
"blender" -b villa.blend --python render_shots.py -- mode=day cams=CAM_Hero
```

## 十、这一轮的自查与修正（模型自审）

先用脚本把"看起来别扭"变成可量化的清单：`audit.py` 用真实墙段（构建时导出的 `walls.json`，不是整层包围盒）逐段比对，输出五类问题，再逐条修。

**第一轮审查结果 → 修正**

| 问题 | 数量 | 根因 | 修正 |
|---|---|---|---|
| 家具浮空 | 12 | 台盆柜体悬空 0.3 m、静室蒲团比木榻面高 0.16、门厅花瓶离条案 5 cm | 台盆柜落地、木榻改按榻面标高摆件、花瓶贴台面 |
| 家具穿墙 | 8 | 衣帽间柜体过宽越过隔墙 0.65 m、书椅/单椅离墙太近、玄关条几压住隔墙 | 重排房间内家具边界 |
| 越出建筑轮廓 | 1 | 客房衣柜 1.8 m 宽放在 3.0 m 墙上偏 0.55 m | 改 1.6 m + 内移 |
| 家具互相穿插 | 26 | 厨房**油烟机做了两遍**（整体橱柜自带 + 另加的吊柜）、衣帽间两个吸顶灯同位置重合、床头柜撞书桌椅、茶几与坐垫互压 | 删重复件、重排 |

**第二轮又抓出 4 个"不符合常理"的真问题**（这类只有看图 + 审图一起才能发现）：

| **树/草/花要精模** | 原来是程序化球团 | 换成 **PolyHaven CC0 成品模型**（见下） |

**成品植被管线**（不依赖 Blender 插件，直接走 HTTP）：

1. `api.polyhaven.com/assets?t=models&c=trees|plants|flowers|ground+cover` 选资产（看 polycount / tags）
2. `api.polyhaven.com/files/<id>` 取 gltf 1k 下载清单 → 连同 `.bin` 与贴图一起拉到 `assets/<id>/`
3. `prep_assets.py`：导入 → 合并 → **Decimate**（jacaranda 3.86M 面 → 19.3 万，pine 39.8 万 → 4.8 万，flower/cover 更低）→ 贴图压 512 → 居中落地归一化 → 存 `assets/<name>.blend`
4. `lib/assets.py`：`bpy.data.libraries.load` append 一次，其余副本 `ob.copy()` 共享同一份 mesh —— 导出的 glTF **只写一份几何**，实例只多节点

现在场景里：**jacaranda 5 株**（背景天际线 4 + 庭院 1）、**pine 4 株**、**flower/cover 30 处**成片花境（院墙内侧、汀步两侧、甲板边、车道边）。GLB 从 15MB 涨到 55MB，其中成品树占大头。
